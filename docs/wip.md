# 未完成与做不到的能力

本文件收录 Flandora 当前**做不到**或**只能近似**的能力，以及各自的原因。动作目录（`flandora/action_catalog.py`）里每个未实现动作的 `wip` 字段都指向这里或 [`needs-user.md`](needs-user.md)，两者共同构成「什么能用、什么不能用」的完整口径。

## 一、微信 PC 客户端没有入口

这一类不是「还没写」，是微信桌面端根本不提供对应操作，任何 HTTP 或 UIA 手段都够不着：

| 能力 | 说明 |
| --- | --- |
| 群管理 | 踢人、禁言、设管理员、改群名、转让群主、设群头像、全员禁言、加群方式 |
| 好友管理 | 删好友、改备注 |
| 点赞与在线状态 | `send_like`、`set_online_status`、`get_online_clients` |
| 精华消息 | `set_essence_msg`、`delete_essence_msg`、`get_essence_msg_list` |
| 表情回应 | `set_msg_emoji_like`（微信桌面端长按消息才有，UIA 够不着） |
| OCR 与翻译 | `ocr_image`、`translate_en2zh` |
| @ 全体成员 | 桌面端没有 `@所有人` 入口，只有手机端有 |
| 合并转发 | 桌面端不能外部构造转发卡片，只能逐条转发 |
| 语音消息 | 必须按住麦克风录制，没有「上传音频当语音」的通路 |
| 系统消息 | 加群请求、群系统消息在桌面端不呈现为可操作对象 |

这些动作在 OneBot 侧一律返回 `status=failed`、`retcode=1404`，`message` 写明具体原因；不会回空对象假装成功。

## 二、可以绕道，但形态受限

| 能力 | 现在的做法 | 代价 |
| --- | --- | --- |
| 语音段 `voice` | 解码成 mp3 文件，走 `send_file` | 对方收到的是文件卡片，双击播放，不是语音气泡 |
| 视频段 `video` | 以文件形式发送 | 文件一定能到对方手里；呈现成文件卡片还是视频气泡由微信客户端按扩展名决定 |
| 引用回复段 `reply` | 跳过该段，正文照常发送；只发 `reply` 时整条返回 `retcode=1404` | 消息没有引用关系 |
| 撤回自己刚发的消息 | 未接通 | 见下节，需要真机确认右键菜单路径 |

## 三、需要真机探索才能定

这三项在代码里留有实现或半实现，但**没有在真机上验证过**，细节与实验步骤在 [`needs-user.md`](needs-user.md)：

- **@ 指定成员**：`uia_sender.send_mention_text` 按「输入 `@` → 比对窗口集合找成员弹层 → 输入昵称 → 点中唯一匹配项 → 输入正文 → 回车」执行，任一步对不上就清空输入框并返回失败。弹层是不是独立顶层窗口、WM_CHAR 能否驱动它的筛选框，需要在真机上看。
- **撤回消息（`delete_msg`）**：微信桌面端只能对「当前会话里的某条气泡」右键撤回，UIA 拿不到气泡与 `message_id` 的对应关系。
- **拍一拍（`send_poke` / `friend_poke`）**：要双击成员头像，头像在消息列表与群成员面板里的定位方式尚未确认。

- **源码模式没有自我替换**：源码运行的更新等于 `git pull` 加重装依赖，面板只提示不给按钮，
  避免出现「点了安装却替换掉正在编辑的工作区」这种事。

## 四、刻意不做

- **在桥接里决定「要不要回」**：@ 过滤、上下文拼接、ASR 全部留给客户端；桥接只负责把群消息全量上报，并如实标记 `is_mentioned`。
- **吞掉错误**：任何未接线的段类型、未实现的动作、发不出去的消息都必须在响应里可见。静默跳过会让客户端把没发生的事记进上下文。

撤回只发 `notice` 且 `message_id` 填 `0`：微信 PC 端的撤回系统消息（`sysmsg type="revokemsg"`）里没有被撤回消息的 id，本地库样本中 `newmsgid` 为空，按内容也反查不到唯一一条。
