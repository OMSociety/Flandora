# Flandora 管理器

Flandora（微信与 OneBot v11 客户端之间的桥接程序）的托盘管理器：一个通知区域图标，
右键菜单管桥接的起停与重启；其余设置都在网页面板里。

管理器就是用户双击的那一个 `Flandora.exe`：启动后把桥接拉起来，此刻开始收发消息。

## 用法

1. **启动**：双击 `Flandora.exe`（源码树里是 `manager/start.bat`，或直接跑
   `python manager/main.py`）。不弹窗，图标出现在通知区域；桥接没在跑就顺手拉起来。
2. **右键菜单**：

   | 菜单项 | 作用 |
   | --- | --- |
   | `运行中` / `已停止` | 当前状态（不可点） |
   | 打开面板 | 用默认浏览器打开网页面板（左键单击图标也是这一项） |
   | 启动桥接 | 拉起桥接；已经在跑时这一项不可点 |
   | 停止桥接 | 停掉桥接（会断掉 OneBot 客户端的连接）；没在跑时不可点 |
   | 重启桥接 | 停掉再拉起：改了配置或桥接卡住时用 |
   | 打开日志 | 用系统默认程序打开 `data/flandora.log` |
   | 退出程序 | 先停桥接、再退出管理器 |

   图标颜色跟着状态走：绿=运行中，灰=已停止；鼠标悬停的提示是同一句话。状态每 2 秒刷新
   一次，菜单项的可用状态也跟着变。
3. **再双击一次**：管理器已经在托盘里时，第二次双击不会起第二个图标——桥接在跑就把面板
   打开，没在跑就安静退出。

## 开机自启

在网页面板的「系统设置 → 安全与服务 → 开机启动」里勾「登录后自动启动 Flandora」。
它写的是当前用户 `Run` 项下的 `Flandora` 值（`HKCU\Software\Microsoft\Windows\
CurrentVersion\Run`），登录时由资源管理器按这条值拉起管理器，管理器再把桥接启动起来。
安装包里的「开机自动启动」任务写的是同一个位置、同一个值，所以面板里看到的勾选状态
就是登录时真正会执行的那一条。

## 源码结构

| 文件 | 职责 |
| --- | --- |
| `main.py` | 入口：单实例互斥量 + 重复双击时打开面板 + 起托盘 |
| `tray.py` | 托盘图标（自绘产品标记）、右键菜单、状态轮询 |
| `bridge.py` | 桥接进程的启停与状态探测（端口、监听 PID、停止事件） |
| `paths.py` | 路径、端口与解释器选择 |
| `start.bat` | 源码形态的启动器（优先用仓库 `.venv`） |

桥接进程怎么起：安装目录有 `Flandora-Bridge.exe` 就直接起它；源码形态则用与管理器
同一个解释器跑仓库根的 `run_bridge.py`。

停桥接分两步：先给桥接发一个命名事件（`Global\Flandora_Stop`），让它自己关微信隔离
桌面、停 OneBot 服务、优雅退出；等满 10 秒还没退，才强杀进程。

强杀那一步按端口找占用者：7999 与 4950 上凡是还在监听的进程都会被 `taskkill /F`
结束（管理器自己的进程除外）。这两个端口被别的程序占着时，停止桥接会连带结束它——
端口是桥接的专用端口，配置里改过端口就以配置为准。

## 依赖

```bat
python -m pip install -r manager/requirements.txt
```

只有 `pystray`（托盘图标与菜单）与 `Pillow`（画图标）两个包。设置都在桥接自带的网页面板里，用浏览器打开。
