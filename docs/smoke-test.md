# 真机冒烟清单

自动化测试只覆盖「同样的输入产生同样的输出」这一层：UIA、微信客户端、OneBot 框架在测试里全是替身。这份清单是真机上的那道闸，按顺序做，每项写完「实际看到什么」，判据一律是**可观察的行为**，不是「没报错」。

文档里的命令统一写 `python`（本机 Python 3.13；若自建虚拟环境，先激活）。临时脚本与截图不要放进仓库。

## 0. 准备

- 备份 `data/`（`config.json`、`id_map.json`、`msg_ids.db`、日志），出问题能整份退回。
- 关掉正在运行的 Flandora 与桥接（管理器里退出，任务管理器里确认没有残留 `run_bridge.exe`）。
- 微信已登录，且是平时在用的那个账号。
- 一个测试好友与一个测试群，允许发测试消息。

## 1. 冷启动

| 步骤 | 通过判据 |
|---|---|
| 删掉（或改名）`data/config.json` 后启动 | 启动后 `data/config.json` 被按示例生成，内容与 `flandora/config.example.json` 一致；日志里出现首次生成的提示，不是崩溃 |
| 观察 `data/flandora.log` | 有新日志、没有 `Traceback`；配置回退告警（若有）以 `WARNING` 形式出现，带具体键名 |
| 面板地址 | 浏览器能打开 `http://127.0.0.1:4950`，界面正常渲染，控制台无红色报错 |

## 2. 面板基础

| 步骤 | 通过判据 |
|---|---|
| 首页状态卡 | 显示桥接未运行、OneBot 入口与连接数、版本号；数字与 `data/flandora.log` 里的一致 |
| 左侧导航逐页点开 | 每页都能渲染，没有整页空白或控制台报错 |
| 打开浏览器开发者工具 Network，刷新首页 | 没有请求返回 5xx；`/api/status` 轮询有间隔，不是疯狂重连 |

## 3. 桥接起停

| 步骤 | 通过判据 |
|---|---|
| 点「启动」 | 状态在几秒内变为运行中；日志出现 OneBot 入口监听与桥接线程启动；面板显示运行时长在走 |
| OneBot 客户端（框架侧）连上正向 WS | 能收到心跳，`status.online` 为 `true`、`status.good` 为 `true` |
| 点「暂停」 | 面板显示已暂停；框架侧心跳变为 `online=false`；**收消息与推送照常**（暂停只影响在线回报，这是当前口径） |
| 点「恢复」 | 心跳恢复 `online=true` |
| 点「重启」 | 桥接线程与 OneBot 入口都重新起来；端口无「已被占用」错误；连接自动重连后心跳恢复 |
| 点「停止」 | 状态变为未运行；**OneBot 入口真的关掉**（框架侧断开、端口不再监听）；再点「启动」能正常起来且不报端口占用 |

> **提示**：第 3 节最后两行是重点——「停止」必须真的关掉 OneBot 入口，「重启」不能在端口上撞车。

## 4. OneBot 契约

用框架侧或调试页发这些动作，逐条看返回：

| 动作 | 通过判据 |
|---|---|
| `get_login_info` | `user_id` 与面板显示一致，`nickname` 不为空串 |
| `get_status` | `online`、`good`、`stat` 字段齐全且与面板一致 |
| `get_version_info` | 返回应用名与版本号，版本号与安装包一致 |
| `send_private_msg` | 测试好友收到消息；返回 `retcode=0` 与 `message_id` |
| `send_group_msg` 带 `at` 段 | 群里出现真提及（名字带底色/@ 样式），不是纯文本 `@名字` |
| `send_msg` 图片段 | 图片真的发出去，不是「发送成功」的空动作 |
| 未实现的动作（动作目录里写 wip 的那些，如 `delete_msg`） | 返回 `retcode=1404`，`message` 说明尚未实现 |
| 瞎编一个动作名 | 返回 `retcode=1405`「不支持的 action」 |
| 未带 token 的请求（若配了 token） | 拒绝连接；HTTP 入口回 401 与 `retcode=1401` |

## 5. 收消息

| 场景 | 通过判据 |
|---|---|
| 好友发文本 | 客户端收到 `message/private` 事件，`sender.nickname` 正确 |
| 群里发文本 | `message/group`，`group_id`/`group_name` 正确，群名不含「(12)」这类人数后缀 |
| 群里 @ 机器人 | 事件里 `is_mentioned=true`；没 @ 时为 `false` |
| 发图片 | 事件里出现 `image` 段，路径指向真实文件；日志里没有把图片当正文推送 |
| 发自定义表情/动画表情 | 事件里出现对应段；日志无异常 |
| 引用一条消息回复 | 事件里第一个段是 `reply`，`id` 与那条消息的 `message_id` 对得上 |
| 撤回一条消息 | 收到 `notice/group_recall` 或私聊对应通知，正文里不再出现「[撤回了一条消息]」假消息 |
| 拍一拍 | 收到 `notice/notify` + `sub_type=poke` |
| 自己发消息 | 自己发出去的消息不会被当作收到的消息推回来：收件源在读库时跳过 `outgoing` 标记的消息（`flandora/wx_source.py`），对端发来的消息照常上报 |

## 6. 配置

| 步骤 | 通过判据 |
|---|---|
| 改一个热生效项（如群名映射）保存 | 立即生效，无需重启；面板顶部提示「其余项需重启」时列出的键与实际一致 |
| 改 `web_bind_host` 为 `0.0.0.0` 且没设密码 | 请求被拒，提示「先设面板密码」，文件未被改动 |
| 设密码后绑 `0.0.0.0` | 保存成功；同一局域网另一台设备能打开面板并要求登录；带上密码能登录 |
| 上传证书与私钥后开 HTTPS | 保存成功；用 `https://` 能打开，证书是上传的那张 |
| 手改坏 `config.json` 里一个值（如 `log_max_mb: 0`）后启动 | 启动不崩，日志出现该键的回退告警，其余配置照常生效 |
| 导出配置（不带凭据） | 文件里没有 `webui_password`/`ob_server_token` |
| 导入刚才那份备份 | 恢复成功，原文件被另存为 `.bak-时间戳` |
| 导入一份带非法值的备份 | 被拒（400），文件原样未动，`.bak` 已生成 |

## 7. 账号与窗口

| 步骤 | 通过判据 |
|---|---|
| 微信换号后重启桥接 | `get_login_info` 的 `user_id`/`nickname` 跟着换；旧账号的群名映射不再串到新账号 |
| 面板里重新选微信窗口 | 绑定成功；发一条测试消息能到达 |
| 隔离桌面上启动微信（若用该模式） | 微信在指定桌面起来，桥接能连上，本机当前桌面不被打扰 |

## 8. 退出

| 步骤 | 通过判据 |
|---|---|
| 面板里停止桥接后退出程序 | 进程退出干净；`7999` 与 `4950` 都不再监听 |
| 直接关窗口 | 没有残留进程；日志最后一行是正常关闭而不是 traceback |
| 管理器启动的形态下再点一次启动 | 不会因为单实例互斥量把自己挡在外面（互斥量已按角色分开命名） |

## 9. 更新

| 步骤 | 通过判据 |
|---|---|
| 旧版本上点「下载并暂存」 | `data/updates/` 出现 `Flandora-v<版本>.zip` 与 `staging-<版本>/`；日志写明是否校验了 sha256 |
| 点「安装并重启」 | 程序退出后出现替换脚本窗口；新版本起来，面板版本号变成新版本 |
| 把暂存的 `Flandora.exe` 换成同样大小、但无法运行的文件后再点「安装并重启」 | 新进程起不来；脚本在观察窗口内判定失败，把备份拷回程序目录并提示原因；旧版本仍能启动 |
