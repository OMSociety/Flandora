# 已知限制

这些是当前版本如实的边界：做不到的事就明说，不猜、不补偿、不替微信实现它没有的能力。

- **语音、文件、视频的本体只取本机已有的**：语音在 `media_0.db` 里是 SILK 数据，桥接转成 WAV 后以 `record` 段推送；文件与视频取微信已落盘的 `msg/file`、`msg/video` 下的明文本体，附 `file`/`video` 段。微信没把本体下载到本机时（大文件、没点开的视频）等 30 秒后只按文字推送，不做 CDN 下载。发送方向不受影响。
- **图片可能是 HEVC 容器**：微信把一部分图片（表情包尤其多）存成私有的 `wxgf` 容器，本体是 HEVC。图片走微信自己留的明文副本（`_h` 高清原图优先，其次 `_b` 预览、主文件中图、`_t` 缩略图；微信只在用户点开图片后才下载 `_h`，没有时只能给中图），没有副本、或对应记录还没同步到解密副本时如实只报 `[图片]`；表情走表情缓存，见下一条。
- **表情要等一次内存扫描**：表情缓存用账号级 seed 派生的密钥加密，seed 只活在微信进程内存里。桥接第一次遇到表情时在后台扫一次（本机实测约 3 秒），这条消息最多等 5 秒；等到了就带图推送，等不到、或者本地根本没有这份缓存（比如微信还没把它落盘）就如实报 `[表情]`。微信重登后 seed 可能变化，会再扫一次。
- **取钥需要一次重新登录**：口令只在登录瞬间存在，等不来，这是微信的设计。
- **图片密钥需要一张没被缓存过的图**：密钥只为正在解码的图片短暂驻留内存。
- **隔离桌面上登录仍需手机确认**：扫码或手机端确认绕不过去。
- **发送必然触发微信自身的窗口消息处理**：已逐项实测否证十几种「不惊动它」的投递方式（PostMessage、SendMessageTimeout、UIA SetValue、SetFocus、Invoke、SetActiveWindow、完全附着线程等），任何向微信投递的输入都会让它升到前台，这是微信自身行为；隔离桌面是绕开它的办法，不是修好了它。
- **一个微信号只能被一份实例驱动**：要跑多个号，用 `isolated_desktop_name` 给每份实例配不同桌面名，并用不同的 `ob_server_port`。
- **视频以文件形式发送**：视频段走文件通道发出，对方一定能收到；呈现成文件卡片还是视频气泡取决于微信客户端。
- **撤回与拍一拍未接通**：两者都要求精确点中某条消息气泡或某个头像，UIA 目前拿不到稳定的定位方式，动作如实返回 `1404`。
- **隔离桌面随桥接进程销毁**：每次重启都要在「微信画面」里重新登录一次微信。
- **未在全新安装的 Windows 上验证过**：开发与测试都在一台已经装了很多东西的机器上完成。

实验过程与数据见 [known-limits-dat-format.md](known-limits-dat-format.md)（本地库的加密封装与实测样本）与 [known-limits-desktop.md](known-limits-desktop.md)（同一桌面里「发得出去」与「微信不升前台」为什么互斥、隔离桌面的代价）；需要在真机上确认的两项（撤回、拍一拍）见 [needs-user.md](needs-user.md)。
