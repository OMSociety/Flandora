# 需要一起动手的实验

这里的每一项都要在**真机**上确认，光看代码定不下来：微信的 UIA 树是黑盒，弹层是不是独立窗口、右键菜单有哪些项、气泡能不能定位，只有跑起来才知道。

## 前置条件

- 微信已在隔离桌面（默认 `WeBotSandbox`）或当前桌面登录，且 Flandora 正在运行（`data/flandora.log` 有输出）。
- 有一个**测试群**（自己和自己两个号，或与信任的人约定好的群）与一个**测试好友**，允许发测试消息。
- 每项实验做完，把「看到了什么」记进本文件的对应小节即可，不必改代码。

## 1. @ 指定成员

- 现状：`flandora/uia_sender.py` 的 `send_mention_text` 已实现完整路径，机制已在真机上验证过，尚未发过真实消息。
- 已验证（在「别管了八卦群」里只输入 `@`、不发送）：
  1. 弹层是**独立的顶层窗口**，类名 `Qt51514QWindowToolSaveBits`、标题 `Weixin`，与搜索弹层同类；`enum_process_windows` 的前后差集能稳定拿到它。
  2. 弹层内部：`GroupControl mmui::ChatMentionList` → `ListControl mmui::XTableView` → `ListItemControl mmui::XTableCell`，每项的 `Name` 就是成员显示名（如 `斯兰德Slandre`、`小苏打`）。
  3. 往主窗口投 `WM_CHAR '@'` 就能打开弹层；继续投昵称前缀（`斯兰`）会就地筛选，弹层窗口不重建。
  4. 点中列表项后，输入框文本里带 U+2005 分隔符——与历史真 @ 消息的存储形态一致，说明选中的是提及对象而不是纯文本。
  5. 弹层打开期间投退格清不掉输入框，要靠 `ValuePattern.SetValue("")` 兜底（`_clear_input` 已有这条兜底）。
- 还需确认（要发真实消息，需测试群授权）：整条路径按回车之后，群里出现的是蓝色 `@昵称` + 正文，而不是「@昵称」四个字。
- 实验：用测试发送页发一条 `[CQ:at,qq=<群成员ID>] 测试`，观察测试群的呈现与日志。
- 判定：出现蓝色 `@昵称` 且同时带正文，即通过；只要日志里出现「没有出现成员选择弹层」或「没能选中」，就把该行日志贴回来。
- 操作提醒：实验时按 `Escape` 可能让微信主窗从隔离桌面上消失（桌面变黑屏），重开桥接即可恢复。

## 2. 撤回自己刚发的消息（`delete_msg`）

- 现状：未接通，动作目录标 `wip`。
- 要确认的：
  1. 在会话里对**自己刚发的气泡**右键，菜单里「撤回」的确切文案与位置。
  2. 那个菜单是不是独立顶层窗口，能不能按名字点中。
  3. 撤回是否需要二次确认弹窗，按钮文案是什么。
  4. 气泡本身能不能通过 UIA 定位（`mmui::` 类名？列表项按索引？）。
- 实验：手发一条消息，右键它，把菜单截图（或 UIA 树里菜单项的 Name 列表）记下来。
- 判定：能稳定定位「最后一条自己发的消息」并点中撤回，才值得接线；否则维持 `wip` 并如实回 `1404`。

## 3. 拍一拍（`send_poke` / `friend_poke`）

- 现状：未接通，动作目录标 `wip`。
- 要确认的：
  1. 群聊里双击成员头像是否触发拍一拍（还是必须右键菜单里选）。
  2. 成员头像是 UIA 可见控件，还是纯绘制（拿不到控件）。
  3. 私聊里双击自己头像的行为（拍自己）。
- 实验：在测试群里双击一位成员的头像，看是否出现「你拍了拍 XXX」。
- 判定：头像能定位并双击命中，才接线；否则维持 `wip`。

## 4. 视频与语音的到达形态

- 现状：`video` 段与 `voice` 段都以文件形式发送。
- 要确认的：对方收到的是文件卡片还是视频/语音气泡；mp4 通过文件发送后能不能直接播放。
- 实验：往测试好友发一个几秒的 mp4 与一段 mp3，截对方视角的图。
- 判定：只影响 `docs/wip.md` 里「形态受限」那两行的措辞，不影响实现。

## 5. 引用回复（`reply` 段）

- 现状：跳过该段，正文照发。
- 要确认的：右键「引用」的菜单文案与位置，以及引用之后输入框的变化（是否出现引用条）。
- 实验：手发一条被引用消息，右键它选引用，观察输入框与发送结果。
- 判定：若引用条是输入框内的独立控件，且可用 UIA 触发，就值得做；否则维持跳过。

## 6. 语音与视频的媒体本体

- 现状：只能拿到 `[语音]` / `[视频]` 占位符，本体解不出来（本机账号里没有任何语音或视频文件可供反推）。
- 要确认的：
  1. 对方发来一条语音后，媒体文件落在 `msg/` 下的哪个子目录（`attach`？`video`？），扩展名是什么（`.silk` / `.amr` / `.mp4`）。
  2. 视频是否有独立的封面图与视频本体两个文件，两者的 md5 怎么对应。
  3. 语音文件是不是微信私有的 silkc 编码（需要解码才能变成可播放的音频）。
- 实验：让测试好友给你发一条 3 秒语音和一个 5 秒视频，然后统计 `msg/` 下新出现的文件路径与扩展名，把目录树与文件大小贴回来。
- 判定：拿到本体文件才谈解码；只有占位符时，`docs/wip.md` 里媒体本体那条保持现状。
