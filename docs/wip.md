# 未完成与做不到的能力

本文件收录 Flandora 当前**做不到**或**只能近似**的能力，以及各自的原因。动作目录（`flandora/action_catalog.py`）里每个未实现动作的 `wip` 字段写明原因：指向本文件或 [`needs-user.md`](needs-user.md) 的逐条登记，值取自 `NOT_QQ` 常量的属于第一节「微信 PC 客户端没有入口」那一类；三者共同构成「什么能用、什么不能用」的完整口径。

## 一、微信 PC 客户端没有入口

这一类不是「还没写」，是微信桌面端根本不提供对应操作，任何 HTTP 或 UIA 手段都够不着：

| 能力 | 说明 |
| --- | --- |
| 群管理 | 踢人、禁言、设管理员、改群名、转让群主、设群头像、全员禁言、加群方式 |
| 好友管理 | 删好友、改备注 |
| 点赞与在线状态 | `send_like`、`set_online_status`、`get_online_clients` |
| 精华消息 | `set_essence_msg`、`delete_essence_msg`、`get_essence_msg_list` |
| 表情回应 | `set_msg_emoji_like`（微信桌面端长按消息才有，UIA 够不着） |
| OCR 与翻译 | `ocr_image`、`translate_en2zh` |
| @ 全体成员 | 桌面端没有 `@所有人` 入口，只有手机端有 |
| 合并转发 | 桌面端不能外部构造转发卡片，只能逐条转发 |
| 语音消息 | 必须按住麦克风录制，没有「上传音频当语音」的通路 |
| 系统消息 | 加群请求、群系统消息在桌面端不呈现为可操作对象 |

这些动作在 OneBot 侧一律返回 `status=failed`、`retcode=1404`，`message` 写明具体原因；不会回空对象假装成功。

## 二、媒体本体在 CDN 上，不在本地磁盘

2026-10-24 让测试账号私聊发了一条语音和一个视频，实测结论：

- 语音是 `local_type=34`，内容是 `<voicemsg voiceformat="4" voicelength="3642" length="5699"
  aeskey="…" voiceurl="7f0c0006…" />`。音频本体由微信 CDN 托管，本地目录里没有对应文件
  （全盘 `*.silk`/`*.amr`/`*.mp4` 计数为 0），要拿本体得实现微信的 CDN 下载与 AES 解密。
- 视频是 `local_type=43`，内容里同样只有 `cdnvideourl`/`aeskey`/`length="2757987"`/`md5`，
  本地只落了缩略图：`msg/video/<月>/<hash>_thumb.jpg`（未加密，可直接读）。
- 所以「媒体本体」不是定位一下文件就能解决的，属于新工程（CDN 协议 + 解密 + silk 转码），
  短期按占位文本上报：`[语音]`、`[视频]`。
- 文件消息同理：`local_type=49` 的 appmsg 里只有 `<appattach>` 的 `attachid="@cdn_…"`、
  `aeskey`、`totallen`，本机不留本体，收件按占位文本上报 `[文件] 名字`。
- 这三类都不做 CDN 下载：那是替微信客户端实现它自己的取件流程，不属于「把本机已有的
  数据如实映射成 OneBot」。

## 三、可以绕道，但形态受限

| 能力 | 现在的做法 | 代价 |
| --- | --- | --- |
| 语音段 `record` | 解码成 mp3 文件，走 `send_file` | 对方收到的是文件卡片，双击播放，不是语音气泡 |
| 视频段 `video` | 以文件形式发送 | 文件一定能到对方手里；呈现成文件卡片还是视频气泡由微信客户端按扩展名决定 |
| 引用回复段 `reply` | 跳过该段，正文照常发送；只发 `reply` 时整条返回 `retcode=1404` | 消息没有引用关系 |
| 撤回自己刚发的消息 | 未接通 | 见下节，需要真机确认右键菜单路径 |

## 四、需要真机探索才能定

这两项在代码里留有实现或半实现，但**没有在真机上验证过**，细节与实验步骤在 [`needs-user.md`](needs-user.md)：

- **撤回消息（`delete_msg`）**：微信桌面端只能对「当前会话里的某条气泡」右键撤回，UIA 拿不到气泡与 `message_id` 的对应关系。
- **拍一拍（`send_poke` / `friend_poke`）**：要双击成员头像，头像在消息列表与群成员面板里的定位方式尚未确认。

- **源码模式没有自我替换**：源码运行的更新等于 `git pull` 加重装依赖，面板只提示不给按钮，
  避免出现「点了安装却替换掉正在编辑的工作区」这种事。

## 五、刻意不做

- **在桥接里决定「要不要回」**：@ 过滤、上下文拼接、ASR 全部留给客户端；桥接只负责把群消息全量上报，并如实标记 `is_mentioned`（真 @）与 `reply_to_self`（引用了自己的消息）。消息段照原样上报，不替客户端往正文里加 @。
- **吞掉错误**：任何未接线的段类型、未实现的动作、发不出去的消息都必须在响应里可见。静默跳过会让客户端把没发生的事记进上下文。
- **猜图片**：消息里的 md5 在本地库对不上（记录被替换、文件已被清理）时，只如实上报 `[图片]` 文本，不按时间邻近猜文件、不拿别的图顶替。图片本体按 `_h`（高清原图）→ `_b`（会话预览）→ `_t`（缩略图）的顺序挑第一个能解的明文副本；微信的 `wxgf` 容器（HEVC）暂时只认不拆。
- **补偿撤回**：微信把撤回后的消息行**原地替换**成 `sysmsg`，原行与本地文件一起消失，`newmsgid` 也常为空。已经推送过的消息不会追发撤回，也不去猜被撤回的是哪一条。
- **绕过界面限制**：会话被收进「折叠的聊天」、气泡右键菜单进不去这类桌面端限制，如实回失败原因，不写旁路（切前台的方案会占用户屏幕，已排除）。

撤回只发 `notice` 且 `message_id` 填 `0`：微信 PC 端的撤回系统消息（`sysmsg type="revokemsg"`）里没有被撤回消息的 id，本地库样本中 `newmsgid` 为空，按内容也反查不到唯一一条。
